# 语义分类（混合规则 + DeepSeek）设计

日期：2026-08-21  
状态：已实现（智能分类默认关闭）

## 背景

当前支出分类依赖 `src/lib/categories.js` 的关键词与京东标签。未命中时默认 `购物 / 日用品`。  
店名（如「老乡鸡」）、菜品/店招（如「骨头汤店」）、时段词（如「早餐」）等常无法命中，需要通用语义能力，又要控制成本与隐私面。

约束：

- 静态前端（Vite + Vue），部署于 GitHub Pages
- 用户约每月记两次账，用量极低
- 选用 DeepSeek；智能分类默认关闭

## 目标

- 在现有规则之上，对「仍为默认分类」的支出做语义归类
- 分类结果必须落在现有 `CATEGORY_MAP` / 规则体系内的一二级分类
- API Key 仅存浏览器本地，不进入仓库
- 关闭智能分类时，行为与现网完全一致

## 非目标

- 不做服务端代理
- 不改收入 / 转账分类流程
- 不训练或托管本地模型
- 不在仓库中提交任何 API Key

## 方案概览

采用三层流水线：

1. **京东标签**（现有 `JD_CATEGORY_RULES`）
2. **关键词规则**（现有 `RULES`）+ **轻量餐饮场景词**（新增，纯本地）
3. **DeepSeek 批量语义分类**（仅当开关开启，且仍为默认 `购物/日用品`）

```
交易说明
  → JD 标签命中？ → 采用
  → RULES / 场景词命中？ → 采用
  → 默认购物-日用品 且 智能分类开启？ → 批量调 DeepSeek
  → 否则保持默认 / 规则结果
```

## 轻量场景词（第 2 层补充）

在不引入 AI 的前提下，先覆盖高置信餐饮形态，例如：

- 时段：早餐、午餐、晚饭、晚餐、夜宵
- 业态后缀/词根：餐厅、饭店、食堂、面馆、粉店、粥店、小吃、火锅、烧烤、烘焙、蛋糕、奶茶、咖啡
- 常见菜品/店招碎片：骨头汤、盖浇饭、麻辣烫、黄焖鸡、沙县、老乡鸡（可少量品牌，非主策略）

原则：宁可少报，不可把超市买菜、粮油误打成三餐；与现有「买菜」规则冲突时，**先匹配的更具体规则优先**（保持 RULES 数组顺序语义）。

## DeepSeek 调用（第 3 层）

### 触发条件

- 设置中「智能分类」为开启
- 已配置有效 API Key
- 支出条目经前两层后仍为 `['购物', '日用品']`
- 用户点击「开始转换」时触发（与现有转换流程绑定）

### 请求

- Endpoint：`https://api.deepseek.com/chat/completions`
- Model：`deepseek-chat`（Flash 档；若官方别名变更，集中在一处常量修改）
- 批量：每批约 40 条，字段含稳定 `id` + 交易说明（备注全文）
- System / User prompt：给出完整允许的一二级分类树；要求只返回 JSON 数组  
  `[{ "id": "...", "c1": "...", "c2": "..." }]`
- `c1`/`c2` 必须属于允许集合；非法则丢弃该条，保留默认分类

### 失败与降级

- 网络错误、401、超时、JSON 解析失败、部分非法：该批或该条保留规则/默认结果
- UI 提示「智能分类失败/部分失败」，不阻断整次转换与导出

### 成本预期

每月 2 次、仅未识别条目批量调用，预计远低于 ¥1/月。不逐条请求。

## 配置与安全

| 项 | 行为 |
|----|------|
| 智能分类开关 | `localStorage`，**默认关闭** |
| API Key | `localStorage`，设置区输入；不写进代码、不进 git |
| 密钥泄露 | 若曾在聊天/截图暴露，须在 DeepSeek 控制台轮换 |

浏览器直连 DeepSeek：Key 会出现在用户本机网络请求中（用户自有 Key）。公开页面不内置共享 Key。

## UI

- 设置入口（页头齿轮或折叠面板）：开关「智能分类」、API Key 输入（密码框）、保存/清除
- 转换中：若开启且有待分类项，显示「智能分类中…」进度（批次数即可）
- 结果表：可选标记 `_aiClassified`（内部字段），便于日后展示「AI」角标；首版可只做内部标记、不强求 UI 角标

## 模块划分

| 模块 | 职责 |
|------|------|
| `categories.js` | 保留 `classify`；增加场景词规则；导出「是否为默认分类」判断与允许分类树 |
| `ai-classify.js`（新） | DeepSeek 批量调用、校验、批处理 |
| `settings`（localStorage 封装） | 开关与 Key 读写 |
| `transform.js` / `App.vue` | 转换流程接入：规则分类 →（可选）AI 补全 → 写回一二级分类 |

## 测试要点

- 开关关闭：老乡鸡等仍可为默认（或仅被场景词命中），行为可预期且无网络请求
- 开关开启 + 无 Key：提示配置 Key，不发起请求或明确失败提示
- 「江苏中石油代付」等关键词路径仍为交通-私家车，不进 AI
- 「早餐」「骨头汤店」在场景词或 AI 下归入餐饮-三餐
- AI 返回非法分类时丢弃该条

## 风险

- 浏览器 CORS：若 DeepSeek 不允许浏览器跨域，需改为用户自备兼容代理或后续加轻量代理；实现时先验证直连，不通再补文档说明
- 模型偶发错分：以允许列表校验 + 默认关闭降低影响
- Key 泄露：仅本地存储 + 文档强调轮换
